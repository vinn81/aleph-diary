플랜두씨 다이어리 2 인증 구현 설명서

결과물 주소
- 배포 후 입력: https://배포주소.example
- 현재 저장소의 첫 화면: index.html

소스 주소
- 화면과 로그인 진입점: index.html
- 가입·로그인·로그아웃: api/auth.js
- 기록 API와 소유권 검사: api/diary.js
- 새 DB용 스키마: db/001_initial.sql
- 기존 DB용 마이그레이션: db/003_auth_migration.sql
- 한 번에 실행할 통합 파일: db/SETUP_ALL.sql

① 무엇으로 붙였나
- Neon PostgreSQL의 users와 sessions 테이블, 서버 전용 Vercel API를 사용했다.
- 비밀번호는 원문이 아니라 Node crypto.scrypt로 salt와 함께 해시해 저장한다.
- 세션 토큰 원문은 HttpOnly, SameSite=Lax 쿠키에만 두고 DB에는 SHA-256 해시만 저장한다.

② 왜 그걸 골랐나
- 기존 앱이 이미 Neon과 Vercel API를 사용하므로 별도 인증 서버를 추가하지 않아 배포 구성이 작다.
- 비밀번호를 직접 저장하지 않고 세션을 서버에서 폐기할 수 있다.
- 기록 테이블에 user_id를 연결하면 GET, PUT, DELETE를 모두 같은 소유자 조건으로 제한할 수 있다.

③ 어디를 어떻게 고쳤나
- db/001_initial.sql에 users, sessions와 diary_days.user_id, 사용자별 날짜 유니크 인덱스를 추가했다.
- 기존에 001을 실행한 DB는 db/003_auth_migration.sql을 실행하면 같은 변경을 적용한다.
- api/auth.js에 가입, 로그인, 현재 세션 확인, 로그아웃을 추가했다.
- api/diary.js는 세션이 없으면 401을 반환하고, 로그인한 user.id로만 기록을 조회·저장·삭제한다.
- index.html은 인증 상태 확인 전 앱 화면을 숨기고, 로그인 성공 뒤에만 /api/diary를 호출한다.
- 기존 미귀속 기록은 첫 가입 시 한 번 첫 계정으로 귀속된다.

④ 안 열리는 것을 확인한 기록
- 아래 VERIFICATION.txt에 성공 요청과 거절 요청을 나란히 적었다.
- 비밀번호, 세션 쿠키, 토큰 원문은 기록하지 않았다. 쿠키는 항상 [REDACTED]로 가렸다.
- 이 작업 환경에는 DATABASE_URL이 없어 원격 Neon에 대한 실제 HTTP 실행은 완료하지 못했다. 따라서 배포 후 그대로 실행할 재현 명령과 기대 응답을 함께 남겼다.

⑤ AI와 나
- AI에게 맡긴 일: 인증 API, DB 마이그레이션, 화면 연결, 재현 가능한 확인 명령의 초안을 작성하게 했다.
- 내가 직접 판단한 일: 기존 Neon/Vercel 구조를 유지하고, 기록 소유권을 세 API 경로 모두에서 user.id로 검사하도록 결정했다.
- AI 말을 따르지 않은 일: 실제 계정 비밀번호나 토큰을 확인 기록에 넣지 않았고, 실행하지 못한 원격 검증을 성공했다고 쓰지 않았다.

⑥ 아직 못 막은 것
- 이메일 인증, 비밀번호 재설정, 다중 기기 세션 목록과 강제 전체 로그아웃은 아직 없다.
- CSRF 방어를 별도 토큰으로 두지 않았고 현재는 SameSite 쿠키와 JSON API 전제로 운용한다.
- 로그인 시도 횟수 제한과 계정 잠금이 없어 공개 서비스라면 레이트 리밋을 추가해야 한다.
- 기존 기록의 첫 계정 귀속은 개인용 마이그레이션 가정이다. 여러 사용자가 이미 존재하는 DB에는 별도 소유자 매핑이 필요하다.

짧은 확인 방법 4줄
- 어디로 가나요: 배포 주소를 열고 /api/auth와 /api/diary 요청을 확인한다.
- 세 단계 안에 무엇을 하나요: 가입 또는 로그인, 기록 조회, 로그아웃 후 같은 조회를 실행한다.
- 무엇이 보이면 통과인가요: 로그인 전과 로그아웃 후 /api/diary가 401이고, 로그인 중에는 자기 기록만 200으로 보인다.
- 안 될 때는 무엇이 보이나요: 화면에는 로그인 필요 또는 인증 서버 오류가 보이고, 응답에는 비밀값 없는 JSON 오류가 보인다.
