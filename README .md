# Plan Do See

계획(Plan), 실제 수행(Do), 회고(See)를 날짜별로 기록하는 개인 다이어리입니다. 가입하거나 로그인한 뒤에만 기록 화면이 열리며, 각 사용자는 자신의 기록만 조회·저장·삭제할 수 있습니다. 화면과 서버 API는 Vercel에 배포하고 데이터는 Neon PostgreSQL에 저장합니다.

- 결과물: https://aleph-diary.vercel.app
- 소스: https://github.com/vinn81/aleph-diary

## 주요 기능

- 회원가입, 로그인, 로그인 상태 확인, 로그아웃
- 사용자별 Plan·Do·See 기록 분리
- 날짜별 목표와 계획 저장
- 실제 수행 시간과 수행 내용 기록
- 회고 저장과 지난 기록 조회
- 달력에서 날짜 이동
- 개별 계획 및 날짜 전체 기록 삭제
- 새로고침 후 서버 데이터 복원

## 인증 구현 설명

### ① 무엇으로 붙였나

Neon PostgreSQL의 `users`, `sessions` 테이블과 Vercel 서버 API를 사용했습니다. 비밀번호는 Node.js의 `crypto.scrypt`로 salt와 함께 해시하고, 세션 토큰 원문은 `HttpOnly`, `SameSite=Lax` 쿠키에만 저장합니다. 데이터베이스에는 세션 토큰의 SHA-256 해시만 저장합니다.

### ② 왜 이것을 골랐나

기존 앱이 이미 Neon과 Vercel API를 사용하고 있어 별도의 인증 서비스를 추가하지 않고 같은 구조 안에서 인증과 데이터 소유권을 관리할 수 있기 때문입니다. 서버에서 세션을 삭제해 로그아웃시킬 수 있고, 모든 기록 쿼리에 사용자 ID 조건을 적용할 수 있다는 점도 고려했습니다.

### ③ 어디를 어떻게 고쳤나

- `api/auth.js`: 회원가입, 로그인, 현재 세션 확인, 로그아웃 처리
- `api/diary.js`: 로그인하지 않은 요청에 401 반환, 조회·저장·삭제에 사용자 ID 조건 적용
- `db/001_initial.sql`: 사용자와 세션 테이블, `diary_days.user_id`, 사용자별 날짜 인덱스 정의
- `db/003_auth_migration.sql`: 기존 데이터베이스에 인증 구조 추가
- `db/SETUP_ALL.sql`: 새 DB와 기존 DB에서 필요한 구조를 한 번에 설정
- `index.html`: 로그인 화면, 인증 상태 확인, 로그인 후 앱 표시, 로그아웃 버튼 연결

기록 목록과 계획·회고 조회는 모두 로그인한 사용자의 `user_id`로 제한됩니다. 저장은 사용자와 날짜의 조합으로 처리하고, 삭제도 `user_id`와 날짜가 모두 일치할 때만 실행됩니다.

### ④ 안 열리는 것을 확인한 기록

2026년 9월 14일 배포 주소에 로그인하지 않은 상태로 요청해 다음 응답을 확인했습니다. 비밀번호, 세션 쿠키와 토큰은 기록하지 않았습니다.

```text
GET /api/auth
200
{"authenticated":false,"user":null}

GET /api/diary
401
{"error":"로그인이 필요합니다."}

PUT /api/diary
401
{"error":"로그인이 필요합니다."}

DELETE /api/diary
401
{"error":"로그인이 필요합니다."}

잘못된 계정으로 로그인
401
{"error":"아이디 또는 비밀번호가 올바르지 않습니다."}
```

첫 화면에서는 로그인 화면이 표시되고 기록 본문은 숨겨집니다. 로그인에 성공하면 기록 화면을 표시하고 `/api/diary`를 호출합니다. 로그아웃하면 서버의 세션 행을 삭제하고 브라우저 쿠키의 유효기간을 0으로 설정합니다.

### ⑤ AI와 나

- AI에게 맡긴 일: 인증 API, 데이터베이스 구조, 화면 연결, 오류 처리와 확인 항목의 초안을 작성하게 했습니다.
- 내가 직접 판단한 일: 기존 Neon·Vercel 구성을 유지하고 조회·저장·삭제 전부에 사용자 ID 검사를 적용하기로 결정했습니다.
- AI 말을 따르지 않은 일: 실제 비밀번호나 토큰을 확인 문서에 넣지 않았고, 직접 실행하지 않은 검사를 성공했다고 기록하지 않았습니다.

### ⑥ 아직 못 막은 것

- 이메일 인증과 비밀번호 재설정은 제공하지 않습니다.
- 로그인 시도 횟수 제한과 계정 잠금이 없습니다.
- 별도의 CSRF 토큰은 없으며 현재는 SameSite 쿠키와 JSON API를 사용합니다.
- 사용자가 자신의 여러 로그인 세션을 확인하거나 한 번에 모두 종료하는 기능은 없습니다.
- 사용자 이름을 잊었을 때 복구하는 기능은 없습니다.

## 데이터베이스 설정

1. Neon 프로젝트의 SQL Editor에서 `db/SETUP_ALL.sql`을 실행합니다.
2. Neon의 Connect 화면에서 pooled connection string을 복사합니다.
3. Vercel 프로젝트의 Settings → Environment Variables에 `DATABASE_URL`로 등록합니다.
4. 적용 대상인 Production, Preview, Development 환경을 선택합니다.
5. 변경된 소스를 배포한 뒤 로그인과 기록 저장을 확인합니다.

실제 데이터베이스 연결 문자열은 소스 코드나 Git 기록에 넣지 않습니다. 별도의 공개용 환경 변수 예제 파일도 제공하지 않습니다.

## 로컬 실행

```bash
npm install
npm run dev
```

실행 전에 로컬 실행 환경이나 Vercel CLI 설정에 `DATABASE_URL`을 직접 등록해야 합니다. 실제 연결 문자열이 포함된 파일은 커밋하지 않습니다.

## 저장 구조

- `users`: 사용자 이름과 해시된 비밀번호
- `sessions`: 해시된 세션 토큰, 사용자, 만료 시각
- `diary_days`: 사용자, 날짜, 하루 목표
- `plans`: 계획, 완료 기준, 예상·실제 시간, 상태와 실제 기록
- `reviews`: 잘된 점, 달라진 점, 이유와 다음 행동

브라우저는 `/api/auth`와 `/api/diary`만 호출하며 데이터베이스에 직접 연결하지 않습니다. `DATABASE_URL`은 서버 함수에서만 사용합니다. 브라우저 저장소는 저장 실패 시 입력을 잃지 않기 위한 임시 초안에만 사용하고 기록의 원본은 Neon DB에 저장합니다.

## 5일 사용 기록

- 1일차: 이번 주의 우선순위를 정하고 중요한 일부터 시작
- 2일차: 오전 집중 시간을 확보하고 미뤄둔 작업의 첫 단계 진행
- 3일차에 들어가기 전 규칙 변경: 오전 집중 작업을 두 번 계획하던 규칙을 한 번만 계획하고 여유 시간을 남기는 규칙으로 변경
- 3일차: 회의와 작업 사이의 전환 시간 줄이기
- 4일차: 운동하고 저녁에는 업무에서 벗어나기
- 5일차: 계획 시간과 실제 시간을 비교하고 다음 주 규칙 정하기

날짜별 세부 기록과 규칙을 바꾼 이유는 `USAGE_5_DAYS.txt`에 정리되어 있습니다.

## 짧은 확인 방법 4줄

- 어디로 가나요: https://aleph-diary.vercel.app의 로그인 화면으로 이동합니다.
- 세 단계 안에 무엇을 하나요: 가입 또는 로그인 → 기록 작성과 새로고침 확인 → 로그아웃 후 기록 API 재요청을 진행합니다.
- 무엇이 보이면 통과인가요: 로그인 중에는 자기 기록만 보이고, 로그인 전과 로그아웃 후에는 기록 요청이 401로 거절됩니다.
- 안 될 때는 무엇이 보이나요: 로그인 필요 또는 인증 서버 오류 안내와 비밀값이 포함되지 않은 JSON 오류 응답이 표시됩니다.

## 배포 후 최종 확인

1. 첫 화면에 로그인 화면이 표시되는지 확인합니다.
2. 가입·로그인·로그아웃이 정상적으로 동작하는지 확인합니다.
3. 로그인한 상태에서 기록을 저장하고 새로고침한 뒤 값이 유지되는지 확인합니다.
4. 로그아웃한 뒤 `/api/diary`가 401을 반환하는지 확인합니다.
5. 서로 다른 두 계정의 목록에 상대방 기록이 나타나지 않는지 확인합니다.
6. 다른 계정의 기록을 수정하거나 삭제하려 해도 원래 소유자의 기록이 유지되는지 확인합니다.
7. 요청·응답이나 화면을 제출할 때 비밀번호, 쿠키, 토큰과 `DATABASE_URL`을 가립니다.
